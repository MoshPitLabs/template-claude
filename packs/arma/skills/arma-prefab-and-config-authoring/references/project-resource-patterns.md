# Resource Verification Checklist

For the current addon, discover and record:

- `*.gproj` dependency GUIDs.
- Actual prefab, config, world, and UI directories.
- Base resource path and GUID.
- Inheritance chain.
- Nearby project resource using the same component or property.
- Corresponding `.meta` files and inbound references.
- Workbench editor used to validate the resource.
- Runtime scenario that instantiates or consumes it.

Do not assume a standard folder layout. Add a pattern below only after it has loaded in Workbench against the target game version. Example paths name their repository (`DLG_*`, `LHDF_*`).

## Verified patterns

### Prefabs: build in Workbench, not by hand

A hand-written `.et` (editable component with UIInfo, labels and budget blocks) crashed Workbench natively (access violation) on every project load once it was registered. Build prefabs through Workbench instead, in the recorded `test_world` or another world the user names for the purpose (see `arma-enfusion-mcp-tooling` safety rules):

1. `wb_entity_create` a `GenericEntity` (or the base prefab to inherit from).
2. `wb_component` add the components; `wb_entity_modify` set properties.
3. `wb_prefabs createTemplate` to write the `.et` and its `.meta`.
4. Delete the temporary entity before handing back.

Workbench sometimes times out on entity creation and creates the entity anyway. After a timeout, `wb_entity_list` before retrying, or you leave a duplicate behind.

### `.meta` for hand-written text resources

Without a `.meta`, Workbench logs "resource not registered ... Setting null GUID" and the resource cannot be loaded or dragged into a world. Shape (resource class per type: `CONFResourceClass` for `.conf`, `StringTableResourceClass` for `.st`, `EntityTemplateResourceClass` for `.et`):

```text
MetaFileClass {
 Name "{GUID}Path/To/Resource.conf"
 Configurations {
  CONFResourceClass PC {
  }
  CONFResourceClass XBOX_ONE : PC {
  }
  CONFResourceClass XBOX_SERIES : PC {
  }
  CONFResourceClass PS4 : PC {
  }
  CONFResourceClass PS5 : PC {
  }
  CONFResourceClass HEADLESS : PC {
  }
 }
}
```

The GUID is 16 uppercase hex digits and must be unique; `resolve_guid` confirms it is unused.

### String tables

Verified in `LHDF_GameMasterAdditions/Language/` and `LHDF_GameMasterAdditions.gproj`.

- Source `.st` (edited in the String Editor). The root needs `ItemClassName`, or the editor fails with "Can't find StringTableItem class" (older BI samples omit it):
  ```text
  StringTable {
   ItemClassName "CustomStringTableItem"
   Items {
    CustomStringTableItem "{GUID}" {
     Id "PREFIX-Feature_Name"
     Target_en_us "Display text"
    }
   }
  }
  ```
  Its `.meta` uses `StringTableResourceClass`.
- Runtime `Language/<name>.<lang>.conf` per language: `StringTableRuntime { Ids { ... } Texts { ... } }`, `.meta` with `CONFResourceClass`.
- Registration in the `.gproj` PC configuration, reusing the vanilla settings ID that mods share:
  ```text
  WidgetManagerSettings WidgetManagerSettings "{AC4BE58770485E02}" {
   StringTables {
    StringTableDefinition "{GUID}" {
     StringTableSource "{GUID}Language/<name>.st"
     ...
  ```
  Editing a `.gproj` needs the brief to name it, or the user's confirmation.

### Game Master placeable entities

- `SCR_EditableEntityUIInfo.Icon` (`.edds`) is tinted by the UI, so it must be a white glyph on a transparent background; an opaque image renders as a solid tinted block. `IconSetName` is ignored for `.edds` icons (it applies to imagesets only).
- The content-browser card picture is the separate `m_Image` field; empty shows a warning-triangle placeholder. `m_bFullBackgroundAssetCard 0` centres the picture instead of stretching it.
- UI textures need width and height divisible by 4 (DXT compression).

### Resource database and GUID identity

- The loose-file dedicated server resolves GUIDs through `resourceDatabase.rdb`. A prefab copied in without its database entry spawned but never replicated. The database is regenerated by opening the project in Workbench; never copy it between working copies.
- Keep one working copy per project GUID. Workbench compiled a stale or packed copy of a project that had the same GUID as the edited one, and edits went into the wrong copy.
- Use `refactor_*` (move, replace GUID, rename project id) only when the brief names the move; they rewrite references across the project. `refactor_merge_duplicate_guids` and `refactor_remove_unused` only diagnose or emit a script for the user.

### Textures

- Workbench registers a dropped PNG but writes the `.edds` only on reimport. Reimport it in the Resource Browser (or use the repository's conversion script if it has one).
- Workshop banners and other art that must not ship belong outside the mod folders (for example `.github/assets`); anything inside a mod folder gets registered and packed.

## Configuration rules

Server owners cannot edit packed configs, so runtime settings come from JSON in the server profile. These rules come from DLG releases that broke existing servers:

- **Sparse overrides.** The shipped default applies wherever the server file is silent. Never write defaults to the profile on first start: the file then wins forever and new defaults never reach existing servers.
- **Built-ins are shipped configs.** The profile holds per-entry overrides only.
- **Scenario defaults are config files** that inherit the mod's defaults, not instance overrides on game-mode components in a world layer.
- **A file that does not parse is never written.** Migrations write only when they actually changed something (compare content, not the path).
- **Ids are scoped by their owner** (shop preset, mod), never shared across catalogs by a bare id.
- **Prefab-only values** (arsenal `MaxItemSize`, volumes) have no script setters; such mods are the stated exception to JSON configuration.
- **Anything a scenario needs to run correctly ships as a scenario default.** The server profile folder holds overrides only; it has been deleted by hand before.
